### B-268 — the page a Spanish reservation ends on is Spanish, date included (2026-09-07, `5f60cab`)

B-267 translated the reservation form and stopped at its redirect. `/reservations` is where that redirect goes, and it is also where the cancel link in the confirmation email lands — so it is the page that says a unit is held, the page that shows when the hold ends, and the page that releases it. It imported nothing from `@/lib/i18n`.

**What it built.** Twenty-four `res.*` keys and four `err.reservation*`, across the page and its two server actions. `generateMetadata` replaces the static `metadata` export and translates the title — unlike the marketing pages B-262 deliberately left English, because this route already carries `robots: { index: false }` and there is no crawler here to keep on English.

**The row's own warning was the smaller of the two things wrong with this page.**

- **The date, which the row named.** `formatWhen` and `formatDay` hardcoded `'en-US'`, so the hold's expiry rendered "Saturday, September 12 at 5:00 PM" underneath a Spanish label — the one fact on the page with a deadline attached, in the language the reader had just said they could not read. Both now take the locale. `timeZone` was already explicit and stays that way: it is the facility's, not the server's, which is what keeps B-228's class out of this even as the tag changes.
- **The status sentence, which it did not.** `<p>This reservation is <strong>{reservation.status}</strong>. …</p>` interpolated a `ReservationStatus` enum value straight into prose. Two defects in one line: an English word inside `<html lang="es">` with no `lang` of its own (3.1.2), and — for `converted` — a sentence that was **false in both languages**. `provision.ts` sets that status when a move-in completes, `reservationByToken` returns the row regardless of status, so a renter who had just signed a lease and paid, revisiting the link in their own confirmation email, was told the unit was *"back available for anyone to take"*. One key per ended status fixes both at once, which is why the fix is three keys rather than one with a placeholder.

**A false comment is what kept that branch unread.** `reservationByToken`'s doc comment said it returns null "for one whose reservation is no longer live". It never has — the page branches on `status` on the line after it calls it, which is the whole reason the `!live` paragraph exists. The comment has said the opposite of the code since B-018, and a reader trusting it would conclude the converted branch was unreachable. Corrected in place, and it now says why the filter is deliberately absent.

**`LOCALE_TAG` moved from `lib/comms/prose.ts` to `lib/i18n`.** B-261 wrote it beside the send path's Spanish prose, which is where it was first needed and not where it belongs: every surface that formats a date, a number or a list needs `en` | `es` widened to a BCP-47 tag, and a public page reaching into the comms module to get `'es-US'` is the wrong dependency for two strings. Values are unchanged, so all thirty-five existing callers in `comms/service.ts` render character-for-character what they did.

**What it reused rather than duplicated**, which is B-267's rule and the reason it has one: `reserve.moveInDate`, `facility.footBy` and `card.perMonth` are the same words for the same things, and a second entry per label is how two surfaces drift.

**No fourth `keyedFieldError` caller**, which the handoff asked for explicitly. The only input on this page is a hidden token, so none of the five action messages hangs on a field; all five go back as the form's summary through `messages()`. `keyedFieldError` counts fields to pick its heading and would have had nothing to count.

**`res.cancelled` joins `MUST_ALSO_DIFFER`** in `tests/i18n.test.ts` — B-267's rule, third use. It is a `status: 'success'`, so the `err.` prefix that earns the untranslated-paste guard would style it red and tell somebody who succeeded that they failed; it still confirms something irreversible, which is exactly the weight the guard exists for.

**The e2e spec takes B-120's first discipline, and it is the first spec in `i18n.spec.ts` that needs any of them.** The page cannot be reached without a real hold, so this one reserves and cancels in the same test — scoped to `demo-e2e`'s `10x10 Test`, seeded at 250 units precisely so holds need not be cleaned up, and the same fixture and the same reserve-then-cancel cycle the English specs in `smoke.spec.ts` already run. The file header said "nothing here mutates shared demo state" and has been corrected rather than left one merge behind. The expiry is asserted on the Spanish weekday rather than a literal date, because the date moves with the run: no English tag produces any of those seven words and `es-US` always produces exactly one.
